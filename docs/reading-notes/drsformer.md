## 二、痛点分析

| 痛点 | 深层原因 | 现有方法的局限 | DRSformer 的解决方案 |
|------|---------|---------------|---------------------|
| 标准 Transformer 全连接注意力引入噪声 | query-key 对间全部相似度参与聚合，不相关 token 的注意力值仍被纳入特征交互 | 密集计算模式放大较小相似度权重，冗余/无关表征干扰恢复 | TKSA：Top-K 自适应选择最有用的注意力值 |
| CNN 局部感受野 vs Transformer 缺乏局部建模 | CNN 受限于局部感受野且与输入无关；Transformer 不擅长建模局部不变特性 | CNN 难消除长程雨退化；Transformer 难捕捉细节纹理 | MSFN：3×3 + 5×5 双分支混合尺度前馈网络 |
| 前馈网络缺乏多尺度信息 | 标准 FFN 单尺度卷积，无法捕捉不同尺度雨纹间的相关性 | 单尺度表示不足以处理多密度、多方向雨纹 | MSFN 引入多尺度深度卷积提取多尺度局部信息 |
| 数据稀疏性与内容稀疏性未联合探索 | 雨分布揭示退化位置与程度，但现有方法未有效利用 | 单一稀疏机制无法同时处理数据和内容层面的稀疏性 | MEFC：混合专家特征补偿器，用注意力作为专家切换器 |

## 三、核心方法

### 3.1 整体架构

![DRSformer 架构图](assets/arch-DRSformer-new.jpg)

DRSformer 基于**层次化编码器-解码器**（改造自 Restormer）：

```
输入雨图 I_rain
  → 3×3 Patch Embedding
  → 4 层级 STB（Sparse Transformer Block）堆叠
    ├── 层级 1-3: 下采样（pixel-unshuffle）+ N 个 STB
    └── 层级 4: N 个 STB + 上采样（pixel-shuffle）
  → Skip Connection 桥接中间特征
  → 全局残差: I_derain = F(I_rain) + I_rain
```

在早期与最终阶段放置 N₀ 个 **MEFC**（混合专家特征补偿器），提供互补特征精炼。

### 3.2 STB（Sparse Transformer Block）

每个 STB 由两个子模块组成：

$$X_l' = X_{l-1} + \text{TKSA}(\text{LN}(X_{l-1}))$$

$$X_l = X_l' + \text{MSFN}(\text{LN}(X_l'))$$

即 STB = **TKSA**（Top-K 稀疏注意力）+ **MSFN**（混合尺度前馈网络），均带 LayerNorm 和残差连接。

### 3.3 TKSA（Top-K 稀疏注意力）— 核心创新

#### 设计动机

标准点积注意力对所有 query-key 对密集计算：

$$\text{Att}(Q,K,V)=\text{softmax}\!\left(\frac{QK^\top}{\sqrt{d}}\right)V$$

但 key 中的 token 并不总是与 query 相关，不相关 token 的注意力值仍参与聚合，干扰清晰图像恢复。

#### TKSA 的关键设计

1. **通道维度注意力**（继承自 Restormer MDTA）：注意力矩阵为 C×C 而非 (HW)×(HW)，对空间维度线性复杂度
2. **Q/K/V 编码**：1×1 卷积 + 3×3 深度卷积
3. **L2 归一化**：对 Q、K 做 `F.normalize(dim=-1)`，保证注意力稳定
4. **可学习温度**：τ 为可学习参数，形状 `(num_heads,1,1)`
5. **Top-K 自适应选择**：不使用单一 k，而是**同时构造 4 种不同稀疏度的掩码并加权融合**

#### 4 路 Top-K 掩码详解

| 掩码 | 保留通道数 k（C 为每头通道数） | 稀疏比例 |
|------|-------------------------------|---------|
| mask1 | C/2 | 50% |
| mask2 | 2C/3 | ~67% |
| mask3 | 3C/4 | 75% |
| mask4 | 4C/5 | 80% |

对每个掩码：
```python
index = torch.topk(attn, k=k_i, dim=-1, largest=True)[1]
mask.scatter_(-1, index, 1.)
attn_i = torch.where(mask > 0, attn, torch.full_like(attn, float('-inf')))
attn_i = attn_i.softmax(dim=-1)    # 非 top-k 位置经 -inf → 0
out_i = attn_i @ v
```

#### 门控融合

$$\text{out} = \sum_{i=1}^{4} \alpha_i \cdot (\text{softmax}(A_i) \cdot V)$$

其中 α_i 为 4 个**可学习标量权重**，均初始化为 0.2。

> **核心洞察**：DRSformer 不去"猜"一个最佳稀疏比，而是让 4 个不同 top-k 比例的稀疏注意力并行计算，再由可学习权重自适应加权融合——这既实现了内容稀疏性，又保留了多粒度信息。

### 3.4 MSFN（混合尺度前馈网络）

**动机**：多尺度雨纹之间存在相关性，单尺度卷积不足。

**结构**：
```python
class MSFN(nn.Module):
    # project_in: 1×1 Conv, dim → hidden_features*2
    # 双路并行:
    #   路径1: 3×3 DWConv → ReLU → chunk → 3×3 DWConv → ReLU
    #   路径2: 5×5 DWConv → ReLU → chunk → 5×5 DWConv → ReLU
    # 两路交叉拼接 → project_out: 1×1 Conv → dim
```

**数据流**：
```
x → 1×1 Conv → split → [x1, x2]
x1 → 3×3 DWConv → ReLU → chunk(2) → [a1, a2]
x2 → 5×5 DWConv → ReLU → chunk(2) → [b1, b2]
→ cat([a1, b1]) → 3×3 DWConv → ReLU  } cat → 1×1 Conv → out
→ cat([a2, b2]) → 5×5 DWConv → ReLU  }
```

### 3.5 MEFC（混合专家特征补偿器）

**动机**：联合探索数据稀疏性与内容稀疏性。

**专家集合**（8 种并行 CNN 操作）：
- 可分离卷积：1×1, 3×3, 5×5, 7×7
- 空洞卷积：3×3, 5×5, 7×7
- 平均池化：3×3

**与传统 MoE 的区别**：不附加外部门控网络，而是用（自）注意力作为专家切换器，根据输入自适应选择不同表征的重要性。

**结构**：
- `OALayer`：GAP → FC → ReLU → FC → softmax，生成专家权重
- `GroupOLs`：按权重对各专家操作做加权组合

> **注意**：Rain200L 与 SPA-Data 不使用 MEFC（因雨纹较简单），需改用 `DRSformer_arch_200L+SPA.py`。

## 三.5 数学推导过程详解

### 通道注意力降复杂度

标准空间自注意力复杂度：
$$O(N^2 \cdot d), \quad N = H \times W$$

DRSformer 通道注意力复杂度：
$$O(C^2 \cdot N)$$

当 C << N（如 C=128, N=256×256=65536）时，通道注意力远比空间注意力高效。

### Top-K 稀疏选择

给定注意力矩阵 $A \in \mathbb{R}^{C \times C}$，对第 i 个掩码：

$$M_i = \text{TopK}(A, k_i)$$

$$A_i[j,k] = \begin{cases} A[j,k] & \text{if } (j,k) \in M_i \\ -\infty & \text{otherwise} \end{cases}$$

$$\hat{A}_i = \text{softmax}(A_i, \text{dim}=-1)$$

$$\text{out} = \sum_{i=1}^{4} \alpha_i \cdot (\hat{A}_i \cdot V)$$

**数值示例**（C=8, 仅展示 mask1, k=4）：
```
原始注意力行: [0.3, 0.1, 0.25, 0.05, 0.15, 0.08, 0.02, 0.05]
Top-4 索引:     ✓              ✓      ✓             ✓
掩码后:       [0.3, -∞, 0.25, -∞, 0.15, -∞, -∞, -∞]
softmax:      [0.42, 0, 0.32, 0, 0.18, 0, 0, 0, 0]
→ 不相关 token 权重归零，聚合更聚焦
```

### 损失函数

$$\mathcal{L} = \|I_{derain} - I_{gt}\|_1$$

简洁的 L1 损失，全局残差连接：$I_{derain} = F(I_{rain}) + I_{rain}$

## 为什么这样做

| 设计选择 | 原因 | 不这样做的后果 |
|---------|------|---------------|
| 通道注意力而非空间注意力 | 空间注意力 O(N²) 对大图不可行 | 显存爆炸、计算缓慢 |
| Top-K 稀疏而非密集注意力 | 不相关 token 的注意力值干扰恢复 | 噪声特征被聚合，恢复质量下降 |
| 4 路不同 k 值融合 | 不同稀疏度捕捉不同粒度的相关性 | 单一 k 值无法适应不同雨纹密度 |
| 可学习门控权重 | 让网络自适应选择最佳稀疏比组合 | 固定权重无法适应不同输入 |
| MSFN 双尺度（3×3 + 5×5） | 多尺度雨纹需要多尺度感受野 | 单尺度 FFN 遗漏尺度间相关性 |
| MEFC 混合专家 | 不同雨纹区域需要不同处理策略 | 单一卷积核无法适应多变的雨纹 |
| MEFC 仅在重雨数据集使用 | 轻雨数据集雨纹简单，MEFC 增加冗余 | 简单数据上过拟合 |
| L2 归一化 Q/K | 防止注意力值过大导致不稳定 | 注意力分布过于尖锐或平坦 |
| 可学习温度 τ | 自适应调节注意力锐度 | 固定温度无法适应不同输入 |

> DRSformer 的核心贡献在于**首次将可学习 Top-K 稀疏注意力引入图像恢复**，通过 4 路不同稀疏度的自适应融合，在保持计算效率的同时显著提升恢复质量。后续 DAWN+ 等工作在达到竞争性能的同时大幅降低了参数量。

## 六、深度分析：为什么这样设计？每一步代表什么？

### 6.1 研究背景：图像去雨的根本难点

与去雾不同，去雨面临的核心挑战是**雨纹的高频稀疏性**：

- 雨纹是**高频窄带信号**：宽度通常只有 1~3 像素，方向接近垂直（受重力影响），但受风影响会有偏移
- 雨纹是**稀疏分布的**：一张 620×460 的图像中，雨纹可能只占 5%~15% 的像素面积
- 雨纹有**多尺度多密度**：细雨（Rain200L）几乎像噪点，暴雨（DDN-Data）有大雨滴和长时间曝光产生的雨丝
- 雨纹与背景**高度纠缠**：雨滴落在树枝、窗户等纹理区域时，几乎无法与背景区分

> **去雨问题的本质**：不是简单的"去噪声"（雨纹不是随机噪声），而是"去除一种结构化、方向性、多尺度的高频干扰"。这使得标准的去噪方法（如 BM3D、DnCNN）效果有限。

### 6.2 逐模块动机深度解析

#### 6.2.1 为什么用通道注意力而非空间注意力？

这是 DRSformer（以及 Restormer）最根本的架构选择。

标准空间自注意力：`A ∈ R^(N×N)`，其中 `N = H×W`。对于 256×256 的图像，`N = 65536`，注意力矩阵有 65536² ≈ 43 亿个元素。**即使分窗口（如 Swin Transformer），空间维度仍然是瓶颈。**

DRSformer 将注意力转到通道维度：`A ∈ R^(C×C)`，其中 `C` 通常为 64~180。即使 C=180，注意力矩阵只有 180² = 32400 个元素——**小了 13 万倍！**

**为什么通道注意力在去雨中有效？**

每个通道可以看作一个"特征检测器"。在训练过程中，网络学习到：
- 通道 1~10：检测水平方向的细雨纹
- 通道 11~30：检测垂直方向的雨丝
- 通道 31~50：检测雨滴的圆形光斑
- 通道 51~180：编码背景纹理、颜色、深度等信息

通道注意力让网络学会**"哪些特征检测器之间应该相互交流"**——例如，"检测水平雨纹的通道"和"检测背景纹理的通道"之间的交互可以帮助网络区分"这是背景纹理还是雨纹"。

**如果用空间注意力会怎样？** 空间注意力回答的问题是"哪些像素之间应该交流"——对于去雨来说，只有极少数像素（雨纹位置）之间的交互是重要的，而密集的空间注意力会把大量计算浪费在清晰区域的像素交互上。

#### 6.2.2 TKSA 的 4 路 Top-K：为什么是这 4 个比例？不是 2 路、8 路？

| Top-K 比例 | 含义 | 适应场景 |
|-----------|------|---------|
| **C/2 (50%)** | 最激进稀疏，只保留一半通道交互 | 细雨场景：雨纹信息量少，需要更聚焦 |
| **2C/3 (~67%)** | 中度稀疏 | 中等密度雨纹 |
| **3C/4 (75%)** | 较保守稀疏 | 重雨场景：雨纹信息量大，需要更多交互 |
| **4C/5 (80%)** | 接近密集注意力 | 极端暴雨：几乎保留大部分交互 |

**为什么用 4 路融合而不是搜索最优的单一 k？**

核心洞察：**不同位置、不同雨纹密度需要不同的稀疏度**。一张暴雨图像中，天空区域可能只需要 50% 的通道交互（雨纹简单），而树叶区域可能需要 80% 的交互（雨纹与纹理纠缠）。

如果只用单一 k 值，要么对简单区域过度计算（浪费），要么对复杂区域计算不足（丢失信息）。4 路并行 + 可学习门控融合让网络**在每个位置自适应地混合不同稀疏度的结果**。

**门控权重 α 的初始化为什么是 0.25（而非 1）？**

初始化为 0.25（1/4）意味着 4 路权重相等。如果初始化为 1（某一路），训练初期该路会主导输出，其他路梯度消失，导致其他路"死掉"。0.25 确保了**训练初期 4 路都有梯度信号**，可以公平竞争。

#### 6.2.3 MSFN：为什么是"交叉拼接"而不是"并行拼接"？

MSFN 的关键操作不是简单地让 3×3 和 5×5 各自处理然后拼接，而是**交叉拼接**：

```
3×3 路的输出 a1 与 5×5 路的输出 b1 拼接 → 3×3 卷积处理
3×3 路的输出 a2 与 5×5 路的输出 b2 拼接 → 5×5 卷积处理
```

**为什么要交叉？**

如果 3×3 只看 3×3 的信息、5×5 只看 5×5 的信息，两路之间的"交流"仅靠最终的拼接——这太晚了。

交叉拼接让 3×3 卷积在处理时**也能看到 5×5 的上下文**，5×5 卷积在处理时**也能看到 3×3 的细节**。这形成了一种**多尺度的特征交互**：
- 3×3 分支获取精细局部细节（雨纹的精确边缘）
- 5×5 分支获取更大范围的上下文（雨纹的方向和密度模式）
- 交叉让两路互相补充

**为什么不直接用一个 5×5 卷积？** 因为 5×5 的参数量是 3×3 的 2.78 倍（25 vs 9），而且 5×5 的感受野虽然大，但对细雨纹（1~2 像素宽）的精确建模不如 3×3。

#### 6.2.4 MEFC：为什么 8 种操作？不是 4 种或 16 种？

MEFC 的 8 个"专家"操作：

| 专家 | 操作 | 适合的雨纹类型 |
|-----|------|-------------|
| 1 | 1×1 卷积（逐像素混合） | 点状雨滴（无方向性） |
| 2 | 3×3 可分离卷积 | 细雨纹（窄、短） |
| 3 | 5×5 可分离卷积 | 中等雨纹 |
| 4 | 7×7 可分离卷积 | 粗雨纹、雨滴光斑 |
| 5 | 3×3 空洞卷积 | 小范围稀疏分布的雨纹 |
| 6 | 5×5 空洞卷积 | 大范围稀疏分布的雨纹 |
| 7 | 7×7 空洞卷积 | 极大范围稀疏雨纹 |
| 8 | 3×3 平均池化 | 雨雾混合区域（雾化雨） |

**8 种操作覆盖了雨纹的完整"形态空间"**：从小到大（1×1 到 7×7）、从密集到稀疏（实心卷积到空洞卷积）、从锐利到模糊（卷积到池化）。

**如果只有 4 种，会遗漏什么？** 比如少了空洞卷积就无法处理"稀疏但大范围"的雨纹（像暴雨中的长雨丝），少了池化就无法处理雨雾混合场景。

**为什么用注意力做专家切换器而不是门控网络？**

传统 MoE 用一个独立的门控网络（通常是 MLP）来决定专家权重。DRSformer 的创新在于**用注意力机制作为门控**：

```
GAP → FC → ReLU → FC → softmax → α₁...α₈
```

这本质上是一个**通道注意力**——网络通过 GAP 获取全局信息，然后通过两层 FC 学会"对当前输入，哪种专家操作最重要"。

**为什么 MEFC 只在重雨数据集使用？**

Rain200L 的雨纹非常简单（主要是均匀的细雨线），标准 STB（TKSA + MSFN）已经足够。在这种简单场景下，MEFC 的 8 个专家反而增加了过拟合风险（更多参数但信息量不够）。SPA-Data 不使用 MEFC 则可能因为真实雨的分布与合成雨不同，MEFC 的专家选择策略在合成数据上训练后迁移性差。

#### 6.2.5 L2 归一化 + 可学习温度：为什么需要两者？

**L2 归一化** `F.normalize(dim=-1)` 将 Q 和 K 投影到单位超球面上：

```
q_normalized = q / ‖q‖₂
```

这保证了 `q · k` 的内积范围是 [-1, 1]，不会因为特征幅值差异导致注意力值爆炸。

**可学习温度 τ** 的作用：控制注意力的"锐度"（sharpness）。

```
attn = (q · k) / τ
```

- τ 小 → 注意力分布尖锐（几乎只关注 top-1）→ 太稀疏，丢失信息
- τ 大 → 注意力分布平坦（接近均匀分布）→ 太密集，失去稀疏性的好处

**让 τ 可学习，网络就能针对不同雨纹密度自适应调整注意力锐度**：细雨（需要更聚焦）→ τ 小；暴雨（需要更全面）→ τ 大。这是 Top-K 稀疏选择之外的**另一种稀疏度调节机制**，两者互补。

### 6.3 消融实验的深层解读

1. **TKSA vs Restormer MDTA 的核心差异**：标准通道注意力对所有 C×C 个通道对计算 softmax。TKSA 通过 Top-K 将大部分不相关的通道对权重置 0。这对去雨特别有效，因为很多通道对之间的交互是无意义的（"检测天空颜色的通道"与"检测雨纹方向的通道"之间不需要强交互）。

2. **4 路 vs 2 路融合**：如果只用 2 路（比如 C/2 和 4C/5），中间的两个比例（2C/3 和 3C/4）被跳过——这会导致"粒度断层"。4 路提供了从 50% 到 80% 的平滑过渡，让门控网络有更精细的选择空间。

3. **MSFN 的交叉设计 vs 简单拼接**：消融实验显示 MSFN 优于 Restormer 的 GDFN（门控深度卷积 FFN）。主要原因是 GDFN 的单一尺度深度卷积无法同时捕获细雨纹（需要小感受野）和雨丝方向（需要大感受野）。

### 6.4 数学过程推导 Walkthrough（Concrete Numerical Example）

用简化数值展示 TKSA 的完整计算过程。

**设定**：C=8（每头通道数），4 路 Top-K 分别为 k=4, 5, 6, 6

**Step 1：L2 归一化 Q/K**
```
q = [0.5, -0.3, 0.8, 0.1, -0.2, 0.6, 0.4, -0.1]
‖q‖₂ = √(0.25+0.09+0.64+0.01+0.04+0.36+0.16+0.01) = √1.56 ≈ 1.249
q_norm = [0.400, -0.240, 0.640, 0.080, -0.160, 0.480, 0.320, -0.080]
```

**Step 2：计算注意力矩阵（设 τ=1.0）**
```
attn[0] = q_norm · k_norm = [0.30, -0.15, 0.25, 0.05, 0.10, -0.08, 0.02, -0.05]
```

**Step 3：4 路 Top-K 稀疏化**

以 mask1 (k=4) 为例：
```
原始:   [0.30, -0.15, 0.25, 0.05, 0.10, -0.08, 0.02, -0.05]
Top-4:  ✓(0.30)    ✓(0.25)    ✓(0.10)    ✓(0.05)
掩码后: [0.30, -∞, 0.25, -∞, 0.10, -∞, -∞, -∞]
softmax: [0.35, 0, 0.30, 0, 0.20, 0, 0, 0]
→ 不相关通道权重归零，注意力完全聚焦
```

以 mask4 (k=6, 保留 80%) 为例：
```
保留前 6 个: 0.30, 0.10, 0.25, 0.05, -0.08, 0.02
掩码后: [0.30, -∞, 0.25, -∞, 0.10, -0.08, 0.02, -∞]
softmax: [0.25, 0, 0.22, 0, 0.20, 0.16, 0.17, 0]
→ 更多通道参与，但最不相关的 2 个仍被排除
```

**Step 4：门控融合**
```
out = α₁·out₁ + α₂·out₂ + α₃·out₃ + α₄·out₄
假设训练后学到的权重: α=[0.35, 0.25, 0.20, 0.20]
→ 网络学会了最信任 50% 稀疏度的结果（细雨场景）
```

> **数值示例的启示**：Top-K 不是简单地"去掉小的"，而是将注意力概率**重新分配到保留的通道上**。通过 softmax 归一化，保留的通道获得了更大的权重——比密集注意力中"均匀分散"的效果更聚焦。

## 七、如果以 DRSformer 作为 Baseline：改善点与可添加模块

### 7.1 现有架构的明确改善点

| 改善点 | 现状 | 问题 | 改善方向 |
|-------|------|------|---------|
| **4 路并行计算冗余** | 4 个 Top-K 注意力同时计算 | 显存占用是标准注意力的 4 倍；推理速度降低 | 用**动态路由**替代 4 路并行：先估计雨纹密度，只激活 1~2 路最合适的稀疏度 |
| **Top-K 不可微** | scatter 操作的梯度通过直通估计器 (STE) 近似 | 梯度估计不精确，可能影响训练稳定性 | 用**可学习的软稀疏掩码**（如 Gumbel-Softmax）替代硬 Top-K |
| **固定稀疏比例** | 4 路 k 值（C/2, 2C/3, 3C/4, 4C/5）是预设的 | 无法覆盖极端场景（如超细雨需要 <50% 稀疏度） | 加入**可学习的 k 值预测器**，根据输入特征动态确定稀疏比例 |
| **无频率域建模** | 纯空间域处理 | 雨纹在频域有明确的方向性特征（高频率垂直方向能量集中） | 加入**方向性频率滤波分支**，用 DCT/FFT 捕获雨纹的频率特征 |
| **MEFC 的专家选择缺乏空间感知** | 基于 GAP 的全局专家选择 | 对整张图用同一套专家权重，忽略了局部雨纹密度的差异 | 加入**空间感知的专家选择**（如滑动窗口注意力或局部专家路由） |
| **L1 损失过于简单** | 仅 L1 像素损失 | 可能导致恢复结果过于平滑，缺乏感知质量 | 加入**感知损失**（VGG 特征空间）或**频域损失**约束雨纹频率成分 |

### 7.2 可添加的推荐模块

**模块 1：方向感知频率分支 (Direction-Aware Frequency Branch)**
- 对中间特征做 2D FFT/DCT，分析频谱中不同方向的能量分布
- 雨纹通常在垂直方向（90°附近）有强高频能量
- 用一个方向选择模块，自适应地抑制雨纹方向的频率成分
- 预期提升：PSNR +0.2~0.4 dB，尤其对方向性雨纹（Rain200H）效果显著

**模块 2：雨纹密度估计器 (Rain Density Estimator)**
- 在编码器前加一个轻量级密度分类器（输出: 轻/中/重/极重）
- 动态控制 TKSA 的门控权重偏好：轻雨 → 更信任稀疏路（α₁ 偏大）；重雨 → 更信任密集路（α₄ 偏大）
- 预期提升：减少不必要的计算（轻雨场景推理速度 +30%），同时保持精度

**模块 3：软稀疏注意力 (Soft Sparse Attention)**
- 用 Gumbel-Softmax 替代硬 Top-K，实现端到端可微的稀疏选择
- 避免 scatter 操作的不可微问题，梯度更准确
- 预期提升：训练收敛速度 +20%，最终 PSNR +0.1~0.2 dB

**模块 4：局部-全局混合专家 (Spatially-Aware MoE)**
- 将 MEFC 的 GAP 替换为滑动窗口池化或局部注意力
- 不同空间区域可以有不同的专家组合：天空区域偏好池化+大卷积；建筑区域偏好小卷积+空洞卷积
- 预期提升：对非均匀雨纹场景（DID-Data、DDN-Data）+0.3~0.5 dB

**模块 5：结构化残差学习 (Structured Residual Learning)**
- 不再只预测"残差图像"（I_derain = F(I_rain) + I_rain），而是分别预测"雨纹层"和"去雨背景"
- 加入雨纹层的结构约束（方向性、连续性）
- 预期提升：对细雨和雨滴场景的效果更好，视觉伪影减少

### 7.3 实验验证建议

1. **第一步（最容易）**：在 L1 损失基础上加入频域损失（FFT/DCT），在 Rain200H 和 DID-Data 上验证
2. **第二步（性价比最高）**：将 4 路并行 TKSA 替换为密度感知的动态 2 路选择，测量推理加速比
3. **第三步（创新性最强）**：用 Gumbel-Softmax 软稀疏替代硬 Top-K，比较训练曲线和最终精度
4. **第四步（应用导向）**：将去雨模型作为 YOLOv8 检测的预处理，测量雨天的检测 mAP 提升

## 八、不足与局限

1. **模型复杂度较高**：论文明确承认模型复杂度较高，未来计划通过剪枝或蒸馏进行模型压缩
2. **4 路并行注意力开销**：同时计算 4 个 Top-K 掩码的注意力带来额外显存和计算开销
3. **Top-K 算子不可微**：`torch.topk` 的索引选择不可微，需用 scatter 近似梯度传播
4. **MEFC 仅适用于重雨**：轻雨数据集（Rain200L）和 SPA-Data 不使用 MEFC，需切换架构
5. **基于 Restormer 改造**：架构受限于 Restormer 的层次化设计，灵活性有限

## 九、一句话总结

DRSformer 通过可学习 Top-K 稀疏注意力（4 路不同稀疏度自适应融合）+ 混合尺度前馈网络 + 混合专家特征补偿器，在 5 个去雨基准上达到 SOTA，是稀疏注意力在图像恢复领域的开创性工作。

### TKSA 伪代码

```python
class TKSA(nn.Module):
    def __init__(self, dim, num_heads, bias):
        self.num_heads = num_heads
        self.temperature = nn.Parameter(torch.ones(num_heads, 1, 1))
        # 4 个可学习门控权重，初始化为 0.2
        self.attn1 = nn.Parameter(0.2)
        self.attn2 = nn.Parameter(0.2)
        self.attn3 = nn.Parameter(0.2)
        self.attn4 = nn.Parameter(0.2)

    def forward(self, x):
        q = F.normalize(self.q_dwconv(self.q(x)), dim=-1)
        k = F.normalize(self.k_dwconv(self.k(x)), dim=-1)
        v = self.v_dwconv(self.v(x))

        attn = (q @ k.transpose(-2, -1)) * self.temperature

        C = attn.shape[-1]
        outputs = []

        for k_val, alpha in [(C//2, self.attn1), (2*C//3, self.attn2),
                              (3*C//4, self.attn3), (4*C//5, self.attn4)]:
            # Top-K 选择
            index = torch.topk(attn, k=k_val, dim=-1, largest=True)[1]
            mask = torch.zeros_like(attn).scatter_(-1, index, 1.)
            attn_sparse = torch.where(mask > 0, attn, torch.full_like(attn, float('-inf')))
            attn_sparse = attn_sparse.softmax(dim=-1)
            out_i = attn_sparse @ v
            outputs.append(alpha * out_i)

        out = sum(outputs)
        out = self.project_out(out)
        return out

### MSFN 伪代码

class MSFN(nn.Module):
    def forward(self, x):
        x = self.project_in(x)           # 1×1 Conv → hidden*2
        x1, x2 = x.chunk(2, dim=1)

        # 路径1: 3×3
        x1 = self.dwconv3x3(x1)
        x1 = F.relu(x1)
        x1_a, x1_b = x1.chunk(2, dim=1)

        # 路径2: 5×5
        x2 = self.dwconv5x5(x2)
        x2 = F.relu(x2)
        x2_a, x2_b = x2.chunk(2, dim=1)

        # 交叉拼接
        out1 = F.relu(self.dwconv3x3_1(torch.cat([x1_a, x2_a], dim=1)))
        out2 = F.relu(self.dwconv5x5_1(torch.cat([x1_b, x2_b], dim=1)))
        out = torch.cat([out1, out2], dim=1)

        out = self.project_out(out)      # 1×1 Conv → dim
        return out
```
